## 1. 产品目标

处理者将文件放入系统，系统自动读取内容、生成简短梗概、提取关键词，并直接从整篇内容生成1–5个最具概括性的中文正式主题，不先生成细主题清单再裁减。限制按整篇文章累计，全库主题总数不限。优先参考原文关键词，按核心对象的常见类别、领域、过程等独立维度生成简短主题；不同论文共享对象或过程时可复用同一主题，也允许有价值的独有主题，合计仍为1–5个。不把对象、方法和结果拼成长名称。先复用规范名称；确实无法合理概括时可用核心原文关键词作主题，不能硬套无关大类。随后依据原始证据生成、审核和分类保存 QA。

系统支持按正式主题名称、别名、细分检索词、上位概念和语义表达搜索，并查找关联的原始文件及 QA。例如，“数学”可以作为正式主题，“三角函数”“圆锥曲线”作为其下检索方向展示；这些细项不必各自成为正式主题或独立 QA 表。

主题发现与 QA 生成随文件处理持续进行，不要求团队提前读完全部资料、确定完整主题清单。用户已测试约 500 篇论文产生 300—800 个主题，这属于需要改进的过细分类结果，不是期望主题数量。首轮验收应比较规范归类前后的正式主题数量、合理覆盖和细粒度检索效果；不预先保证压缩到某个数量。

文档识别、QA 生成和审核使用公司允许的 GLM 服务及公司凭据。主题语义搜索按用户 2026-10-15 授权使用本地开源轻量 Embedding，不发送主题或查询到外部服务。本地程序负责解析、数据计算、任务管理、检索计算、校验和可靠写入。发布后提供双击启动的本地应用，新人无需命令行、Python 环境或提示词知识。

### 1.2 第一版范围

**当前可运行初版**：文件上传及拖入、PDF/PNG/JPG/WebP/CSV/TXT/MD 证据准备、梗概与较宽主题、具体检索词、公司 GLM 图文生成和审核、六字段预览、人工核对入库/排除、已入库QA汇总表格及编辑重审、CSV 总表及按主题/文件导出、名称/别名/中文关键词搜索、图片预览、任务租约及有限恢复。正式界面只展示实际投入资料，无文件时三项统计为 0；合成样例仅用于内部测试。页面已简化：仅保留文件总数、正式主题、已入库 QA 三个统计卡片，横向等宽排成一行，展示名称、数值和单位，上传区以“文件解析”为标题，说明为“选择或拖拽文件到此处，支持jpg、png、pdf文件”，不显示特点宣传行和四步流程说明，不显示顶部工作区提示条及页面标题版本标签；页面底部不再显示品牌、接口或模块说明页脚。顶部状态使用“模型就绪 / 模型待配置”，QA汇总导出按钮使用“导出文件”。

PDF 按页直接提取文字用于 QA 生成与审核，不将纯文字页转存成图片，也不额外导出 TXT/MD 文本文件；内部文字证据、真实页段及 hash 继续保留以支持审核和恢复。原生空白页、纯白无文字的扫描页不生成图片。含实际显示位图或矢量图形的页面保存完整页图（144 DPI），不做区域裁剪或自动分图。有可读文字的图文页另登记同页段文字视图；没有文字层的扫描页仍保留真实图像供公司 GLM 识别，不能仅因肉眼看似文字就删除。文字 QA 的 image 为空，视觉 QA 传原图；不强制每份文件生成图片题。AI 单批最多约 12,000 个正文字符、32 个证据单元及 2 张图片；单个单元可能超过批次阈值；超过16,000字符的文字在冻结前本地无重叠拆成至多16,000字符的片段，保留全文、真实页段和字符偏移，不再因单元过长直接使整篇失败。含图页仍只保存完整原图，长文字另存分段文字视图；视觉请求传真实图片，不重复附带整页长文字。列表和搜索只返回摘要与数量，证据正文、候选和图片在详情中加载；图片延迟加载。详情直接读取已保存完整图片，不再运行裁剪预览或读取其缓存；内部原始证据及 QA 引用保持冻结。解析期间每 10 页续期任务租约，模型响应缓存可复用；已完成全文分类的失败任务直接复用主题结果。内容读取仍覆盖全文，默认最多两批并发，仅返回简短内容要点；整篇1–5个概括主题直接在原有首批QA生成中产生并事务登记，不逐批创建细主题，不按数量拒绝入库。短文件保持一次整篇分类。同一公司网关请求设置 reasoning_effort 为 low，图片能力已再次实测。请求使用临时短证据编号，返回后恢复持久ID；原文、真实图片与审核绑定保持完整。生成每批最多3组中英对照（最多6条语言记录），默认整篇文字约3–5组、图片0–2组，合计5–7组；审核只传实际被候选引用的证据及真实图片，不跳过审核。页面显示批次进度和阶段耗时；失败保留错误类别、模型终止原因、耗时与已完成批次，重试先恢复未完成审核。文字与图片分别安排生成机会，达到总量5组后仍可在7组内补图片，不固定凑到7组；长文档的识别总耗时随证据量增加，图片存储随实际图像证据量增长。当前证据元数据仍整份保存在 SQLite JSON 中，尚未完成逐页断点恢复和超大扫描件的内存/吞吐验收。

**当前限制**：每份最多 25MB，PDF 不设页数上限（`max_pages: null`），文件大小超限不截断；自动区域裁剪已按用户要求回退，含图页保留完整页图；扫描件不能仅凭 PDF 对象判断其是否只有文字；当前无目录选择/文件夹监控、完整语义局部修复、全文向量召回、后台聚类、主题管理工具、自动提交、服务器图片上传、导出 ZIP 快照和安装包。检索支持主题/别名/关键词匹配，以及本地主题语义推荐；默认优先中文，专业短语与跨语言质量仍需验收。以下详细章节包含尚待完成的目标架构。

首个完整版本支持单机本地应用、目录批处理、文字与扫描 PDF、独立图片、CSV、动态主题、质量审核、按主题 CSV 导出、中文短词搜索、上下位关系检索、恢复和用量记录。当前主题语义召回使用本地轻量嵌入；模型不可用时保留本地基础检索。

TXT/Markdown 已支持按段读取。XLSX、HTML/XML 和 NetCDF 在独立适配器中逐步加入。格式未实现时明确显示不支持，不能将“计划支持”显示成处理成功。DOCX、PPTX、音视频、多人共享服务和数据库外部写入为后续扩展。

第一版不要求训练或部署本地大模型，不进行外部知识补答，也不强制对全库论文正文向量化。固定任务流程已足以实现本项目的 Agent 式自动化；自由规划、任意命令执行和 Function Calling 不是启动条件。

### 1.3 直接导入图片（2026-10-20）

在“文件处理 → 文件解析”选择或拖入 PNG、JPG/JPEG，可与 PDF 混合投入。每张图是一份独立资料，自动进入同一任务队列：保存完整图片 → 从实际图像生成梗概、1–5个中文正式主题及最多10个检索词 → 生成中英配对 QA → 对照同一原图共同审核 → 预提交校验 → 确认入库。主题搜索、原图详情、QA汇总编辑重审及六字段导出沿用原流程。只有可靠视觉知识点才出题，不能凭文件名或外部常识补造。

- PNG（包括透明 PNG）和 JPG/JPEG 保留原始字节、分辨率与元数据，不重新渲染或转码；浏览器及公司接口分别使用正确的 `image/png`、`image/jpeg` 类型。WebP 沿用 PNG 兼容副本。
- 当前本地原件保存在 `runtime/live/originals/<文件ID>/`，冻结图片在 `runtime/live/assets/images/<文件ID>/`；`source` 为 `原件持久路径|image-0001|中文主主题`，`image` 为真实冻结图片路径。独立图片无页码；预览只通过已登记 asset_id，不开放任意路径。相同内容重复导入复用已有记录，失败重试复用冻结证据及成功响应，旧历史图片不改写。
- 沿用图片最多2组双语知识点（最多4条记录），不把图片译文算成新考点、不从正文截图凑图表题。低于文档默认5组时会如实提示数量不足，但通过审核的完整配对仍可受控入库；没有有效主题或知识点时明确失败/不足。
- 上传入口每份最多25MB；视觉输入另外受原图5MB、4000万像素限额约束，超限或内容与扩展名不符时说明原因，不静默压缩、缩小或裁剪。图片写入失败不得生成或提交相关 QA。
- 速度措施：PNG/JPG 不经过 PDF 页面渲染，不新增 OCR、独立选图或图像识别调用；正常单图是1次分类、1次生成和1次共同审核。PDF 解析分支与生成调度未改，审核不减少；异常恢复与失败组修订仍按已有规则执行。正常调用数和本地准备优化不代表公司接口响应时间恒定。
- 服务器部署后 PNG/JPG 与论文放在同一资料库，使用稳定资料ID、版本/hash及配置持久目录管理。**当前实现是本地导入；服务器资料库接入、持久目录适配及部署验收尚未完成。**

## 2. 开发边界及与父项目的关系

本 README 是新系统的实施基线，目录内的 `AGENTS.md` 是后续编码代理执行约定。用户后续指令优先。

新系统继承父项目的知识质量和六字段规范，但采用独立运行架构：直接调用公司 GLM API，使用自己的任务库、校验和提交模块。根据用户最新要求，本项目的 source 改为三段式“本地路径｜页段定位｜主题”，覆盖之前的四段式来源设计。父项目原有运行方式和已有数据不改动。

具体边界：

- 新代码、开发虚拟环境、测试、缓存、临时脚本、构建包及运行数据放在本目录内；工具链确需系统临时目录时，只放临时文件并清理，不形成第二个项目目录。
- 父目录的原始资料、参考 XLSX、根目录 `QA.csv`、`.qa_work` 和原有流水线不作为新系统默认写入目标。
- 不导入父项目脚本作为运行依赖；需要兼容的业务规范在本目录实现并测试。
- 用户明确选择外部来源目录后，只读扫描或复制导入，原文件不修改。
- 不扫描整个桌面或父项目来推断正式来源。仅处理用户选择的文件、目录或本项目 `runtime/inbox/`。
- 本地开发只写本项目的运行目录；未来服务器运行通过配置的存储适配器保存文件和图片。当前仅设计服务器存储契约，不部署服务器、不下载正式论文图片。
- 本项目 source 按用户新规则记录文件持久本地路径、真实 page/seg 定位及该条 QA 主主题；不再使用固定全局主题前缀。内部文档 ID、证据 ID 与类型另存，不增加正式列。

**服务器资料接入要求（2026-10-15 确认、2026-10-20 补充，尚未实现）**：服务器已有统一资料库，部署版从同一库选择、登记并读取 PDF 和 PNG/JPG 原图，不要求重新上传或在项目目录持久复制资料库原件。资料库保存文件内容或文件位置均可作为后续适配对象，具体接口部署时确定。应用保存来源标识、版本/hash、真实页段及处理结果；内部文字证据、真实图片、QA 和任务数据放到配置的持久存储；PDF 文字仅用于生成、审核及回查，不额外导出为文本文件或文字页图片。需识别原文件更新/删除，保持冻结证据与历史来源一致；非本地来源的 source 第一段兼容映射另行明确，不虚构本地路径。下文“保存导入副本”描述当前本地模式，服务器资料库模式以本要求为准。

## 3. 用户操作与界面

### 3.1 初次配置

管理员通过配置文件或初始化工具一次性配置公司接口地址、允许模型、凭据引用、主题匹配规则、生成规范、存储位置、并发与用量记录。系统执行实际能力检测，文本/图片能力不足时在文件处理模块提示。第一版不增加独立管理员设置页面，密钥不展示给日常处理者。

新人打开应用后，拖入文件或选择文件夹即可开始；管理员可关闭自动开始，改成确认一次批次后执行。原生文件夹选择或本项目收件箱是本地应用功能，不能仅靠浏览器上传控件声称可以获取任意本机目录。

### 3.2 页面规划：三个模块

| 模块 | 主要内容 |
| --- | --- |
| 文件处理 | 投入文件、梗概、主题标签、阶段进度、QA 六字段预览、原文/原图对照、异常与数量不足提示、结果下载 |
| 主题模糊搜索 | 按词或语义搜索正式主题及其细分检索方向，显示关联文件、匹配类型、分页；具体关键词可筛选对应文件；点击文件查看结果 |
| QA汇总 | 全部已入库QA的六字段表格，按首次入库时间倒序分页，查看证据、编辑中英版本、共同重审并保存、导出 |

QA汇总作为第三个模块，集中展示正式入库记录。文件详情、候选QA与证据预览仍采用模块内展开区域或抽屉。审核异常也在文件处理模块中解决；导出按钮附在文件或批次结果中。主题归并、别名治理、日志和报告保留后台能力，第一版不建设独立主题管理、报告或配置页面。

文件处理列表展示“文件名称｜简短梗概｜正式主题｜处理状态｜合格 QA 数”；展开后按六字段显示 QA，关键词作为可选详情。主题模糊搜索展示“正式主题｜命中关键词/关系｜涵盖文件”，细分词标记为“检索方向”而不是新增正式主题；没有直接文件的上位分类沿登记关系汇总文件并去重。

普通页面使用“已完成”“待检查”“图片不清晰”等业务语言，不展示提示词、JSON、模型参数或任务锁细节。详细诊断供管理员查看。

进度只统计真实完成项，不用准备进度代替生成进度。主题归并或语义索引尚未完成时，允许查看基本结果，显示“语义索引更新中”。

### 3.3 QA汇总：表格与编辑（2026-10-20）

表格是已入库数据库的窗口。正式数据仍存本地 SQLite 的 `qas`，刷新页面不会丢失；未入库候选不显示。服务器独立双库为后续部署目标，本轮没有另建远程库。

- 每行一条 zh/en 记录，六字段完整保留；表格显示六个正式字段与操作按钮，不显示入库时间列；采用11px正文字号、紧凑行距和单元格内边距。时间仅用于后台排序，不进入六字段或CSV。默认每页20条，按 `created DESC, id DESC` 稳定倒序；同一时间按ID固定排序。编辑不改变首次入库时间。分页按当前数据读取，有新入库时刷新重新排列，不承诺跨请求的固定快照。
- 点击“查看 / 编辑”打开中英对照窗口，查看原文及按asset_id读取的完整原图。问题、依据摘要、答案可编辑；source/image/language只读，避免改变来源证据。历史单语只编辑原有版本，不补译；尚未完整入库的双语组先回文件处理补齐。
- “保存并审核”表示用户提交本次修改。服务端校验两版预期hash，持久保存修改和原版本，创建同一任务库中的低优先级任务，由现有唯一worker领取；每次只审核本组，传同一真实证据及真实图片，不重新解析全文，不自动改写用户编辑内容。
- 模型检查事实、范围、知识价值、重复和翻译等义，绑定两版hash及证据hash。通过后复用受控预提交/提交校验，在同一事务内更新候选与正式两条记录。失败整组回滚，表格和CSV继续使用原版。文件/证据/图片变化、版本冲突、重复问题及失效租约均不可覆盖正式数据。
- 修改状态为等待审核、审核中、已保存、未通过或审核异常，表格显示状态、编辑窗口显示原因；拒绝/失败的草稿仍可打开修改，异常可重试。历史原文、旧审核和错误事件保存在 `qa_revisions` / `events`。当前无删除、批量编辑、任意修改来源/图片、独立历史浏览或恢复按钮；不提供语言筛选。

实际接口：`GET /api/qas?page=1&page_size=20`（最多100条）、`GET /api/qas/{id}`、`POST /api/qas/{id}/revisions`、`POST /api/qas/{id}/retry`。编辑请求为 `versions` 数组，每项仅含 `id,expected_hash,input,thinking,output`；双语须提交两版。写请求沿用本机会话/来源校验。列表不携带原证据，详情按需读取。导出仍调用 `/api/export`，中英全部导出且严格六列。查看、翻页不调用GLM；修改审核会消耗公司额度，不承诺额外审核零耗时。

本轮验证：171项自动测试通过，其中14项覆盖QA汇总，包含最新排序与分页、中英共同重审、单语/残缺配对、草稿保留、版本冲突、重复、源文件变更、失效租约、断点续跑和文件任务优先；模拟HTTP解码校验修改审核实际传入原PNG。浏览器隔离资料实点完成编辑→排队→审核→表格更新，并验证正式库0条时的空态。前端语法与差异检查通过。本轮未调用真实公司GLM，不能当作真实论文编辑质量验收；正式库未提交候选或修改问答。截图保存在 `runtime/qa-summary-check/`。

## 4. 总体架构与技术选型

```text
本地启动器 / 文件选择 / 收件箱
                 |
       本地操作界面 + HTTP API
                 |
       应用服务：事务、配置、事件
          /                   \
   文档及 QA 工作队列        索引及主题整理队列
   解析 / 分析 / 生成        主题向量 / 关系审核
   审核 / 修复 / 提交        别名整理 / 缓存更新
          \                   /
          SQLite + 证据和运行文件
                     |
              主题检索 / 受控导出

文档生成/审核 -> 统一公司 GLM 客户端 -> 公司允许的端点
主题语义检索 -> 空闲时本地 ONNX CPU 子进程 -> SQLite 缓存
```

| 层 | 初始选择 | 实施理由与限制 |
| --- | --- | --- |
| 后端 | Python 3.11+、FastAPI、Pydantic | 与解析和数据处理集中在同一运行环境；版本在建工程时锁定 |
| 网络 | HTTP 客户端、统一 GLM 适配器 | 可配置公司网关及能力差异，不把供应商参数散落到业务代码 |
| 前端 | 本地静态 HTML/CSS/JavaScript | 优先满足表格、搜索、证据预览；复杂度增长后再评估前端框架 |
| 状态库 | SQLite、版本化 SQL 迁移 | 单机持久化任务、关系、审核和事务；启用并验证外键 |
| 并发 | 独立 worker、持久队列、限定解析进程和 API 并发 | 长任务不依赖请求连接存活，不用仅存在内存中的任务列表 |
| 原文解析 | PyMuPDF；CSV 标准库；其他格式按需依赖 | PDF 渲染和正文提取分工；统计由代码计算 |
| 基础检索 | 名称/别名/关系索引，加适配中文的词项检索 | 两字查询单独覆盖，不直接假定默认分词器可用 |
| 语义检索 | 本地 BGE small 中文量化模型 + SQLite 缓存 | 已实现主题短文本索引，模型只在空闲子进程加载；全文/文档摘要向量化未实现 |
| 发布 | 启动器、冻结运行环境、目标平台安装包 | 候选 PyInstaller；每个平台分别构建及测试 |

SQLite 可采用 WAL 支持本地读写并行，但仍只有一个写入者；数据库事务要短，网络调用和长模型推理不能放在写事务中。运行库不放网络共享盘。锁等待、重试、检查点和备份流程需要实现及测试。[SQLite WAL 官方说明](https://www.sqlite.org/wal.html)

FastAPI 提供请求返回后的后台任务功能；本项目长任务另外使用持久队列和租约实现恢复，不能把一次 HTTP 后台函数当成可靠作业系统。[FastAPI 官方说明](https://fastapi.tiangolo.com/tutorial/background-tasks/)

## 6. 端到端处理流程

### 6.1 主流程

1. **登记与去重**：确认用户选择的来源；分块计算内容 hash，保存来源位置和只读导入副本。
2. **准备真实证据及图片**：解析正文，固定真实页段定位；保存含图页完整图片到配置存储，登记路径、hash 和真实位置，记录不可用页及排除原因。
3. **领取分析任务**：worker 领取本项目任务库中的任务，获得固定证据与租约。
4. **梗概及分类信息识别**：GLM 从证据中提取关键词、细分方向、范围及较宽主题建议；长文档分片后聚合，关键词不自动成为主题。
5. **优先归类再登记**：检索现有主题、别名、定义和覆盖边界，优先归入已有主题；只有无法合理覆盖的独立较宽方向通过判定后新增，保存正式主题及关键词关联、索引事件。
6. **选题与生成**：冻结合法“证据单元＋主题”引用后领取生成任务；依据一个单元选择实质知识点及主主题；程序按文件路径、page/seg 和主主题组装 source，按实际图片路径组装 image。
7. **结构校验及语义审核**：六字段校验后，GLM 重新对照真实证据审核事实、范围、价值、重复和主题归属。
8. **局部修复**：最多按配置修复有限轮，重新校验与审核；无法修复的候选拒绝或待检查。
9. **预提交校验**：确认来源、审核 hash、租约、重复、权限和批次状态。
10. **受控提交及导出**：先事务保存合格 QA，再产生或更新导出快照；失败能恢复、不重复追加。

短文可以在一次分析调用中同时提取梗概、主题和知识点；生成、审核仍保持清晰步骤。长文按实际上下文预算分片，不能仅按字符数声称满足 token 上限。超长完整单元单独处理；不能截断证据后生成完整答案。

文档主题分析可以覆盖多个单元，QA 的事实依据仍严格限定为一个单元。梗概、分类路径、跨单元主题聚合结果只用于路由和检索，不能成为 QA 的补充事实来源。

### 6.2 文档范围及计数

梗概有 `provisional`（初步）和 `complete`（分析覆盖完成）状态；遇到未读正文、不可读页面或未处理分片，记录覆盖缺口。界面不能将局部摘要显示成全文已分析。

每篇文字约3–5组、图片0–2组，合计5–7组双语知识点是整篇累计目标，完整时为10–14条六字段记录，不是每个主题、每页或每个分片分别凑数。中英译文共享一个知识点，不用于增加考点数。候选组数、完整入库双语组数和入库记录条数分别统计；只入库一版不计完整双语组。根据不同可靠知识点分配目标，没有证据的主题不强制出题。并发 worker 通过文档计数及目标预留协调，避免同时将剩余目标各算一遍。

达到目标后可停止补充 QA；主题分析是否覆盖完仍单独跟踪。任务全部处理完但不足最低数量时，保存可靠记录并标记 `under_min`。零候选进入有原因的证据不足结果，不创建空 QA，也不无限重新领取。

### 6.3 后台流程

主题/关键词/摘要变化事件 → 限额领取索引任务 → 生成或复用向量 → 召回少量相近主题 → 必要的 GLM 归类及关系判断 → 更新别名、检索词归属或合并映射 → 更新索引版本和缓存。

全库聚类仅作为可选、低优先级的周期整理任务，不出现在每篇论文的生成路径中，也不作为搜索的前置条件。

## 7. 多模态证据与文件适配

| 格式 | 处理策略 | 关键边界 |
| --- | --- | --- |
| 文字 PDF | 直接提取文字用于 QA，不另存文本文件或纯文字页图片；含实际图像/矢量图形的页面保存完整页图 | 多栏文本顺序、表头和公式需核实 |
| 扫描 PDF | 页面渲染并传 GLM 视觉模型 | 低清晰度明确拒绝相关 QA，不按文件名猜测 |
| PNG/JPG/JPEG | 原字节保存完整图片，直接传公司视觉模型归类、生成和审核 | 单图不超过5MB、4000万像素；不虚构页码，不自动缩小；模型质量以实测为准 |
| WebP | 保留导入原件，沿用完整 PNG 兼容副本 | 转换后仍受5MB视觉输入限额约束 |
| CSV | 保留表头、真实记录及范围，按需计算 | 缺失分母/单位或计算依据时不补造 |
| XLSX（扩展） | 表/单元格定位、值与公式状态 | 不将无缓存公式结果默认为有效数值 |
| NetCDF（扩展） | 真实变量、显式切片、缺测/缩放、坐标与统计 | 切片不是全量，时间保留单位及 calendar；日期转换需单独核验 |
| HTML/XML（扩展） | 实质文字和节点/块定位 | 不执行 JS；拒绝危险实体及不受控网络获取 |
| TXT/MD（已支持） | 按完整段落与句子保存定位 | 语料指令作为数据，不执行 |

证据单元在任务生成之前冻结：文档版本、unit_id、unit 顺序、文件持久路径、真实 page/seg 与 locator、原文、language、已保存图片及路径、证据 hash、解析版本及已核查状态。最终 source 由合法单元和 QA 主主题共同确定，单元内部身份不依赖 source 字符串唯一识别。

图表以同一真实页面为证据范围，保存实际图像/矢量图形的合并区域并纳入附近文字标签和图注，保留图题、对象、坐标、图例、单位及必要脚注。整页扫描图无法按 PDF 对象可靠区分文字与图形时保留原扫描证据，不把未知区域当作空白。第一版不跨页组合。表头或限定在另一单元、必须拼接才能回答时跳过。

正式 `image` 仅一个字符串路径。论文图片 QA 引用任务中已登记并已保存的那张图片；当前保留完整页图及其中的坐标、图例与脚注，不做区域裁剪。模型可接收同一证据单元内的图片和已登记上下文，但不能拼接其他单元。未来支持多图输出必须另行版本化，不用路径列表冒充单一路径。

视觉生成与审核分别传入同一真实图片；保存输入副本 hash、转换参数和原图对应关系。OCR/图像解释文本是衍生信息，不独立替代原图。QA 依赖视觉信息时，任务没有登记或模型没有成功接收图片就禁止提交。

CSV/NetCDF 的派生计算必须在准备阶段保存输入范围、算法、结果及版本，登记为可追溯证据；之后重新生成合法任务。不能在生成过程中让模型临时口算并补进原 source。普通统计运算不调用 AI。

### 7.1 论文图片提取、下载与服务器保存

1. 当前通过同一次页面解释读取文字和已显示的位图元数据，再读取轻量矢量边界；忽略未显示的资源图、页面背景/边框和单纯水平文字装饰线，不因文字短就认定为图片页。纯文字不渲染、不另存 TXT/MD；空白页不登记图片资产，物理页码保持原序。
2. 含已显示位图或矢量图形的页面保存完整 PNG 页图（144 DPI，保留页面旋转、图注与正文），不自动裁剪或按图号拆分；内部记录真实页段。整页扫描图保守保留；最终分辨率的纯白扫描页跳过，不用降采样或宽松阈值丢弃稀疏证据。
3. 论文引用的外部图片仅在明确可访问的授权来源范围内下载，不自行搜索相似图片替代原图。
4. 本地开发保存到 `QAproject/runtime/assets/images/`；服务器部署时由存储适配器保存到配置的服务器持久目录，例如 `/srv/qaproject/assets/images/<document_version>/page-0008.png`。
5. 当前登记完整图片路径、内容 hash、文档关联与真实页码；证据单元保存 page/seg 和定位。后续存储适配器所需的格式、尺寸、版本等元数据不增加正式 QA 字段；当前不新增裁剪坐标。
6. 图片保存成功、内容及可读性核验通过后才冻结生成任务。上传/下载/写入未完成时，不把临时路径或不存在的服务器路径写入正式 image；失败可恢复。

这里的“下载论文图片”对 PDF 当前为含图页完整渲染保存；需要服务器存储时把这些真实图片保存到服务器。图片来自原论文，而不是 AI 生成图像。[PyMuPDF 图片处理官方说明](https://pymupdf.readthedocs.io/en/latest/recipes-images.html)

### 7.2 模型接收图片与页面展示

`image` 是数据追溯用的持久存储路径，不是证明模型已看图的标志。后端读取图片并按公司接口支持的方式传实际内容，例如获准的图片上传、编码字节或模型可访问的受控 URL；实际方式由能力检测确定。不能只把 `/srv/...png` 这样的服务器文件路径当成模型可以访问的图片地址。

文件处理模块通过受控 asset_id 预览图片，由后端把存储路径映射为展示响应。服务器绝对路径不直接成为浏览器地址；临时预览 URL、签名 URL 不写入正式 image。视觉生成及审核均保留实际传图记录，低清晰度或无法确定图文对应关系时拒绝相关候选。

## 8. GLM 接入、配置与调用策略

### 8.1 统一客户端

所有智能操作通过一个适配层：`analyze_document`、`generate_qa`、`review_qa`、`review_topic_relation`、可选 `embed_text` 和 `expand_query`。禁止业务模块另行接入其他模型提供商、第三方 OCR AI、搜索 AI 或隐式回退。

管理员提供公司端点和模型 ID。不要假定公司网关等同智谱公网，也不要推断一个 key 自动具备所有模型及嵌入路由权限。文本与视觉可使用不同的公司允许 GLM 模型，仍使用同一公司凭据。

公开 GLM-4.6V 文档提供图文输入示例；实施必须用实际公司接口验证。[GLM 视觉官方文档](https://docs.bigmodel.cn/cn/guide/models/vlm/glm-4.6v)

远程 Embedding-3 属于智谱文本向量接口，仅在公司允许该模型及同一凭据访问时启用，当前未接入。2026-10-15 用户已授权并启用本地开源主题嵌入，见21.5节；文档生成与审核继续遵守公司 GLM 限制。[智谱嵌入官方文档](https://docs.bigmodel.cn/cn/guide/models/embedding/embedding-3)

### 8.2 先做能力检测

记录能力版本、检测时间及实际结果：文本、图片传输方式、允许模型、结构化输出、图片格式与大小、上下文/输出限制、可选嵌入、公司级并发/额度。图片检测使用合成测试图并确认图中信息，不能只测试请求未报错。

模型输出必须为可解析的完整内容。结构化输出不可用时采用明确 JSON 提示与本地严格解析。截断、空内容、错误结构不视为成功，不用 `reasoning_content` 代替答案。

## 9. 动态主题模型

### 9.1 较宽正式主题与具体检索词分开

当前主题命名采用独立维度和简短规范名：先根据原文关键词及全文归纳核心研究对象的通用类别，再按有价值的领域或过程补充主题，总计1–5个。通常2–6字，必要专业术语保留完整，不机械截短；不把对象、方法、条件和结果拼成类似论文标题的长标签。具体物种/品种/牌号、步骤及冗长修饰语留作检索词。相同对象的不同研究、不同对象的相同过程都可共享对应主题。示例不构成分类清单，新类别照常新增。

正式主题用于文档分类、QA 主主题、source 最后一段及分表，采用能够覆盖一类研究问题的稳定概念。具体对象、方法、变量、算法、地域和研究情景可以作为检索词，但不会仅因为被提取就生成正式主题。主题仍须有实质正文支持，不把偶然背景词当论文主要分类。

以下仅为分类结构示意，不是对现有文档的真实提取结果：

| 较宽正式主题 | 细分检索方向/关键词 | 保存方式 |
| --- | --- | --- |
| 数学 | 三角函数、圆锥曲线 | 一个正式主题及相应检索词，检索词分别关联实际文件 |
| 海洋生态 | 浮游植物、叶绿素、生态多样性 | 在生态主题下按实际正文登记具体方向 |
| 海洋能源 | 海上风电、潮汐能、波浪能 | 作为检索方向，是否需要正式子主题由统一粒度规则决定 |

同义词可作主题别名；上下位词作细分检索方向。例如，三角函数不是数学的同义词，不应把它设置为完全等价别名。细词搜索应筛选确实含该知识方向的文件，不能返回整个宽主题下全部文件。

名称相似只是候选线索。最终判断是：同义复用、细方向归入宽主题、仅相关保留关系，或不同领域保留独立主题。不能将同名不同义或只是相关的主题盲目合并，也不能为了数量少把全部资料塞进一个无区分度的大类。

粒度规则、典型分类样例和主题定义随配置版本统一。初始可以建立少量核心主题，也可以从空库开始自动发现较宽主题；不要求先完整阅读全部论文。不设置未经验收的主题总量承诺。

正式主题数量按有效规范主题 ID 统计，排除检索词、待归类候选及已合并历史 ID；不能把所有词项或数据库历史记录行数当成当前主题总量。

### 9.2 优先复用与严格自动新增

1. 从文档证据提取关键词、细分方向、主题建议和支持位置，先区分“检索词”与“正式分类”。
2. 本地召回少量已有主题及其别名、定义和边界；GLM 在同次分析或限定判定中检查哪一主题能够合理覆盖。
3. 同义表达复用规范主题 ID，按需添加别名；更具体的研究方向归入既有宽主题，保存为检索词，不新建表。
4. 只有现有主题确实无法覆盖、候选不是已有主题的细分/同义/仅个案标签、且定义具备稳定分类价值时，才自动登记新的较宽主题及 ID。
5. 地区、年份、样本、单个指标或一次算法组合本身不足以触发新增正式主题。方法确为论文实质领域时，可以归入适当方法类主题；不得一刀切排除。
6. 归属不确定时保存待归类候选/关键词及后台事件，不直接增加正式主题数量。证据可靠的 QA 可先生成候选；主主题未确定时等待归类后再正式提交 source，不用“其他”冒充已完成分类。
7. 后台只对新增信息召回少量相近主题，按定义和边界处理归并；无必要不做额外模型调用，不重算全库。

每篇成功归类的文章正式主题最少1个、最多5个；1个已足够时不凑满5个。此上限按整篇文章累计，不是每批5个，全库主题总数不限。优先选择核心研究对象、主要问题及有独立价值的主要方法/交叉领域；偶然背景、引用文献、地区年份和细算法词不作为主要分类。分批读取仅提取内容要点，不生成正式主题。读完全文后，模型直接概括为1–5个正式主题；多批新文件把这一工作合并到原有首批QA生成请求，正常路径没有新增独立主题整理调用。短文件仍一次分类，不先生成大量细主题后由程序裁至5个，也不要求用户筛选。未选方向及细词参与全文统一筛选，每个文件合计最多10个有效检索词；保留词项的真实支持单元，不扩展QA可用证据。

主题粒度以可跨论文共用为准：先参考原文明确列出的关键词，归入物理海洋、海洋生态、海洋化学等通用领域；适用时至少一个宽主题，同时允许有价值的独有主题，总计1–5个。不能只用论文标题式标签；不能把所有资料都塞入海洋观测。原文没有可合理归纳的宽类时允许以核心关键词作正式主题，不硬套无关分类。主题相似词合并和宽主题归类都自动执行规则内判定；不要求处理者逐词确认。新增正式主题保留理由和证据，管理员可定期纠正。归类结果为空时标记失败、允许重试，不以“其他”等占位主题伪装成功；待处理/失败文件在完成归类前可以为0个。历史超限标签由系统通过唯一worker自动重归类并保留旧ID到新正式主题的文件级来源映射，原问答、证据及审核hash不改写；不以旧标签超过5个为由拒绝入库或要求用户手工迁移。全库主题增长过快仍应检查粒度与漏归并，不批量硬删历史主题。

### 9.3 关系类型、合并与拆分

| 类型 | 含义 | 搜索与保存规则 |
| --- | --- | --- |
| `broader/narrower` | 上位与细分 | 允许多上位；层级无环；沿已登记层级展开 |
| `related` | 相关但非包含 | 单独展示语义相关，不冒充下属分类 |
| `alias` | 同一主题的不同叫法 | 规范化查询指向同一主题 ID |
| `merged_into` | 曾有重复主题现已归并 | 旧 ID 保留重定向，历史引用不失效 |

细分检索词与主题的“所属方向”另存，不把所有 finer 关系都提升为正式子主题。两个原先过细的正式主题如可由同一宽主题定义覆盖，可合入该规范主题，原名称保留为有文件对应关系的检索方向；同义名称则作为别名。正式子主题只在分类尺度需要且通过新增门槛时创建。

关系保存 `proposed/usable/verified/rejected` 状态、判断来源和版本。明确自动判定的关系可设 usable；不明确关系保留 proposed，并在搜索中与已用层级关系区分。管理员验证不改变原始证据。

合并只改变规范映射及关联，记录理由和事件；不悄悄覆盖 QA 正文及历史 source。source 保留提交时主题名称快照，当前搜索和分表经规范主题 ID 映射；需要把历史 source 主题更新为新名称时执行有记录的来源迁移、结构校验和新快照，不改原文证据。限制重定向链、防止循环和并发重复创建，用事务重新检查规范名称/映射。

拆分必须重新审查具体文件/QA 的归属，不按原主题批量复制给所有子主题；保留历史和可撤销记录。自动新增不等于自动拆分全部历史数据。

## 10. 增量检索与模糊搜索

### 10.1 三条召回路径

| 路径 | 索引对象 | 主要解决的问题 |
| --- | --- | --- |
| 名称/别名/词项 | 正式主题名、别名、检索词及必要摘要 | 简称、局部词、中文短词、具体研究方向 |
| 分类/方向关系 | 主题层级、检索词归属、词与文件关系 | 搜“数学”展开其正式子类和三角函数等检索方向；细词只取对应文件 |
| 可选向量 | 主题定义、检索词说明及文档摘要 | 不同说法的相关召回；不把结果直接升级为正式主题 |

搜索先匹配正式主题、别名或检索词，再经对应关系取得文件和 QA。宽主题查询分页汇总所属资料并展示细分方向；具体词查询只取有该词/方向支持的文件及 QA，并显示归属正式主题。已知分类与方向展开不受向量 Top-K 截断；语义相似只能补充候选，不能保证找全。

名称/别名精确优先，其次层级匹配和词项匹配，再展示语义相关候选。混合结果可采用 RRF 合并排名，业务关系优先级单独保留。[RRF 官方说明](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/reciprocal-rank-fusion)

结果返回正式主题、命中的检索词及匹配理由，区分正式主题与检索方向；文档按内部文档版本 ID 去重。搜“圆锥曲线”可以返回“数学”主题及实际支持圆锥曲线的文件，不把所有数学文件都视为具体词命中。QA 级细词匹配采用对应知识点/证据关联，不直接复制文档全部关键词。

### 10.2 中文短词与自由查询

“数学”等两字词必须有独立测试。SQLite FTS5 trigram 全文匹配不支持少于三个 Unicode 字符的子串，不能直接将它当作完整中文模糊检索方案。[SQLite FTS5 官方说明](https://www.sqlite.org/fts5.html)

基础方案使用名称/别名精确表、分类词与关系索引，并增加适配中文的分词或短子串路径。错别字纠正及自由表达可后续增加 GLM 查询扩展；扩展只召回库内记录，不把 AI 临时编出的主题当作已入库结果。

当前实现：已知主题查询只读本地缓存。首次自由查询需要向量时，在文件任务空闲后通过本地开源嵌入子进程计算；常用查询向量缓存。主题更新不必重新计算未变化的查询向量，但排名随主题索引版本失效。模型不可用时显示基础检索结果，不隐式切换其他 AI 服务。远程公司嵌入及 GLM 查询扩展仍为可选后续能力。

### 10.3 增量更新与一致性

主题/关键词与文档关联及索引待办在同一事务写入，使用持久 outbox 防止“已入库但索引事件丢失”。本地名称、别名、关键词及可用分类/方向关系更新后即可检索；向量及深入关系整理稍后完成。

后台只计算新增或内容变化的记录，按模型、维度、文本 hash 和索引版本缓存。事件以实体 ID＋版本为幂等键；过期事件跳过；失败可重试并显示积压。可从权威数据重建索引，不需要重生成 QA。

用户已有 300—800 个细主题结果可作为归并测试输入，转为较少正式主题及较多检索词。二者数量分别统计，检索词不增加正式主题表数。初期可以先进行本地精确向量计算，大规模时按测量切换近似索引；全文段落向量化另行评估。

### 10.4 聚类的职责

聚类用于低优先级发现同义候选、可归入共同宽主题的过细分类及异常粒度；其结果需要定义与边界判断，不能仅按相似度改正式分类。新增文档不触发全库重算。已有细主题归并后保留检索词与真实文件关联，减少正式主题而不丢失检索入口；不预设必须采用 K-means。

## 11. QA 格式、分类与质量

### 11.1 正式六字段

```csv
input,thinking,output,source,image,language
```

| 字段 | 要求 |
| --- | --- |
| `input` | 具体知识问题，写明必要对象、地区、时期、指标及条件，独立可理解 |
| `thinking` | 针对本题原文的简短依据及必要推导摘要，不保存长推理链 |
| `output` | 直接完整回答，单位、口径、条件、不确定性及因果边界准确 |
| `source` | 三段式 `本地路径\|真实定位\|主题`；PDF用page/seg，独立图片用image-0001；由程序按合法证据及QA主主题确定 |
| `image` | 已保存的真实图片路径；服务器部署后为服务器持久图片路径；无图使用空字符串，不使用 null |
| `language` | 当前记录语言为 `zh` 或 `en`；每个新知识点生成中英两条记录，证据原语言另存 |

### 11.2 source 页段定位与主题规则

PDF source 示例，仅说明格式，不是正式语料：

```text
/srv/qaproject/documents/example.pdf|page-0008-seg-0003|海洋能源
```

- 第一段是该文档在处理端的持久本地文件路径。本地开发为实际本机路径；将来文档保存在服务器时为服务器上的本地文件路径。记录导入副本路径，并在内部保留用户原始来源位置，避免引用上传临时文件。
- 第二段的 `page` 使用 PDF 物理页，从 1 开始；印刷页码另存。`seg` 使用该页内可回查的证据段编号，从 1 开始，编号及原文/位置随解析版本固定，不能用 QA 序号代替。图像证据段映射到该页真实完整页图及asset_id，不要求裁剪区域或虚构正文段落。
- 第三段使用这条 QA 提交时的较宽主主题规范名称，不填每个细关键词。一篇论文多主题时，各条 QA 按实际考点归类；辅助主题和细词内部保存，不增加 source 段数。分类更宽不会改变问题和答案所需的具体对象、时间、条件及证据范围。
- 程序从任务注册表组装三段值，模型不编造文件路径、页段号和主题。校验页码存在、段号可定位、主主题获准、主题归属受证据支持。
- 三段值中若有 `%`、`|`、换行等保留字符，采用统一的可逆转义；普通路径按原样显示。解析器先分三段再还原，不能简单依赖不受约束的字符串切分。
- 非分页格式不得虚构 page：独立 PNG/JPG 使用 `image-0001`，如 `/srv/library/example.png|image-0001|海洋观测`；CSV 使用真实 `record-起点-终点` 等定位，扩展格式使用真实 sheet/cell/node/seg；仍保持 `文件路径|真实定位|主题` 三段结构，并在格式适配器声明定位 schema。

内部文档 UUID/内容身份与展示文档 ID 分开。展示 ID 仍可采用清理后的首个登记文件名加 MD5 前 8 位，保存完整 hash 并检查碰撞；不再写入 source。相同内容改名后复用内容版本和持久副本，记录新的来源别名；内容变更建立新版本。解析配置改变导致段号或图像范围变化时建立新证据版本，不能使历史页段号悄悄指向新内容。

### 11.3 image 保存路径与六字段示意

论文图片 QA 的 image 示例：

```text
/srv/qaproject/assets/images/<document_version>/page-0008.png
```

路径由存储服务返回并核验，不由模型填写。source 指向论文及其真实页段，image 指向实际保存的图片。生成时只使用纯文字依据的 QA，image 为空；依赖图片的 QA，image 必须为对应已保存图片路径。

以下六字段 JSON 仅作格式示意，问题和答案不代表真实知识证据：

```json
{"input":"包含对象、指标和范围的具体问题","thinking":"对应原文或图像的简短依据摘要。","output":"由实际证据支持的完整答案。","source":"/srv/qaproject/documents/example.pdf|page-0008-seg-0003|海洋能源","image":"/srv/qaproject/assets/images/example/page-0008.png","language":"zh"}
```

主题 ID、qa_id、任务 ID、模型、审核结果等内部元数据保存在库和旁路清单，不增加正式六列。

### 11.4 候选与主题关联

生成调用可以返回有包装的中间响应：候选引用、六字段 QA、topic_keys 和 skipped。正式记录仅保存六字段 QA；主题、候选及配对 ID 保存在内部关联中。内部包装字段不混入正式候选。

GLM 只能从当前任务给定的证据单元及主题键中选择。任务冻结合法单元与主主题的组合、页段定位及实际存储路径，程序组装 source/image 并核验；未知引用拒绝。每条 QA 依据具体知识点设置一个主主题，可增加有证据支持的辅助主题；未确定主主题时在文件处理模块标记待检查，不导出到猜测的表。

### 11.4.1 中英配对生成、分开保存（已实现）

一次生成调用返回 `pairs`，每组包含共同的 unit/topic 和 `zh`、`en` 两个版本，各有 input/thinking/output；程序组装相同的 source/image 和各自的 language，事务保存为两条严格六字段候选。配对 ID 保存在 `qa_pairs`/`candidate_pairs`，不增加 CSV 列。每批最多3组，两种语言不分别再走生成流程，且不翻译整篇资料。

同一次审核对两种语言逐条核对原始证据，并检查语言正确和翻译等义：数字、单位、公式、对象、专名、时间、条件、否定、因果及不确定性均须一致。同组两个版本不互相判为重复；其他知识点仍参与去重。审核记录绑定两条候选 hash 及原证据 hash，任一版本改变后不能使用旧审核提交。模型审核失败或缺失时禁止提交；人工确认不能跳过该门槛。

页面按组展示中文与 English，两条记录分别核对、入库或排除；只采用一版时不计完整入库双语组。缺失版本、空字段或非法引用不保存残缺组，记录原因，不用单语凑足目标。原文语言无需与目标语言相同；跨语言事实及翻译质量仍须人工核对，不以本地字母检测冒充语义验证。

“重新核验本组”调用 `POST /api/candidates/{candidate_id}/rereview`，由同一任务队列仅审核本组及被引用的证据/真实图片，不重复生成或全文分析。请求带 expected_hash，活动文件任务期间拒绝重复排队。失败可重试，已完成批次保留。显式重新核验创建独立审核任务和缓存键，重新调用模型；失败任务续跑可复用该任务已完成响应，历史审核保存在事件中。自动改写修复尚未实现。

导出使用 `GET /api/export`，可按文件/主题限定范围，暂不提供中英语言筛选；旧链接附带 language 参数也统一返回范围内全部已入库语言记录。每条仍严格六列。列表/首页的“已入库 QA”按记录条数统计，详情另示双语组数，不新增首页统计框。

数据库采用增量建表与任务列迁移，保留旧单语记录及已入库内容，不自动补译；旧单语在详情单独标注，不计新双语目标。旧的未入库单语候选需点击重新核验，获得绑定当前内容的审核后再提交。提示词、模型及完整输入参与缓存键，旧单语生成缓存不能冒充双语结果；仅调整输出预算不会使已完成的有效响应失效，全文解析及已完成分类可复用。

### 11.5 逐条审核门槛

- 有概念、机制、条件、比较、方法、结果解释或有支持的应用价值。
- 单个证据单元支持整个答案及其依据摘要。
- 必要对象、时间、地区、样本、单位、币种、分母、情景和口径完整。
- 不把相关性写成因果、预测写成事实、建议写成已证实效果。
- 不把特定样本结论扩展为无条件普遍规律。
- 排除文件概述、页数/行列数、目录、格式、文件名和任意索引值等考点。
- 排除同一事实的不同问法，跨主题复制仍按同一考点处理。
- 不因主题标签或外部常识补出原文缺少的论证。
- 每条问答的 input/thinking/output 与自身 zh/en 标签一致，答案完整，thinking 具体简短；两个版本等义且都受同一原证据支持。

规则校验处理结构、合法引用、图片路径、语言、精确/近似重复和数字单位警示。数字不逐字出现不一定错误，允许的派生必须有登记计算证据；不能靠字符串比对宣称事实已验证。

GLM 审核对照原文或真实图像，保存检查项、支持位置、问题与决定。同服务/同模型审核可能重复错误，上线质量通过人工标注和抽查评价，不以模型自评分替代。

### 11.6 自动与人工提交

开发及试点初期采用人工复核模式；产品自动模式达到约定验收后启用。正常记录可以自动通过，不要求处理者逐批签字。具体策略由管理员配置。

审核记录绑定候选 hash、证据 hash、提示词版本、模型和审核策略。只有有效审核记录且预提交校验通过的候选能提交；不能设置一个默认 reviewed 标志绕过事实审核。任何人工或模型修改都形成新候选版本，并重新进行必要审核。

修复上限初始为 2 轮，可配置；每轮只修改有问题的候选并重新审核。证据不足、图像不可读不要求模型反复补答。默认存在未解决拒绝行时不整批提交；允许显式记录“丢弃拒绝行、提交已通过项”的部分提交策略。

## 13. 任务、租约与故障恢复

任务状态：`queued → leased → running → succeeded`；可进入 `retry_wait`、`waiting_review`、`skipped`、`failed` 或 `cancelled`。状态迁移由服务控制，不能手工修改数据库将成功任务恢复成待处理。

文档业务状态另外保存：待解析、处理中、QA 已完成、部分覆盖、低于最低数、证据不足、失败；多个 shard 的完成数不能直接作为整篇完成。

worker 使用唯一名称，领取和续租事务化；租约到期前检查持有者。晚返回的旧 worker 结果可归档，但不能覆盖新结果或提交。默认串行或少量受限 API 任务，只有实际配置和容量允许时扩大并发。

幂等键包括文档内容/证据版本、阶段、提示词版本、模型、业务配置和已冻结输入。追加 QA 采用新补充任务，不能重放旧任务来增加数量。

| 故障 | 处理方式 |
| --- | --- |
| 输入文件仍在复制或打开中 | 检查稳定性并延迟读取，避免读到半个文件 |
| 单文件解析失败 | 保存原因，其余文件继续；可换配置创建新任务 |
| 图片提取/下载/服务器保存失败 | 保留错误和可恢复步骤，禁止将不存在图片写入正式 image；无关文字 QA 可继续 |
| 公司鉴权/额度失败 | 暂停相关模型队列，提示管理员，不无限重试 |
| 网络超时或可重试服务错误 | 有限退避，记录费用可能已产生的未知状态 |
| 模型输出截断/非法 JSON | 保留脱敏响应，缩小任务或有限修复，不提交截断候选 |
| 程序关闭或崩溃 | 恢复队列、过期租约与持久响应，从最近已完成阶段继续 |
| 索引失败 | 保留基本检索，后台重试并展示延迟，不阻断 QA |
| 导出失败 | QA 已提交状态保持，快照任务重试，不重生成 QA |
| 磁盘不足 | 停止新的写入步骤，保留旧完整产物和事务记录 |
| 某主题无可靠知识点 | 记录证据不足，不编造题目达到配额 |

缓存依据完整输入及规则版本。人工修改、解析变化、模型或策略变化需建立新版本；缓存命中不等于自动适用新规范。

## 14. 提交、分表、路径与迁移

### 14.1 内部记录是唯一事实源

本项目内部 `qas`、审核和主题关联是权威记录，CSV/XLSX 等是版本化导出快照。预提交校验只返回报告；真正提交事务保存 QA、审计与导出事件。重复请求返回原结果，不重复追加。

SQLite 提交与文件导出无法假定是一个跨存储原子事务，因此分别跟踪“QA 已入库”和“导出已完成”。文件失败由持久 outbox 重试，界面不能谎报两个阶段均完成。

### 14.2 主题分表策略

默认每条 QA 进入主主题表；辅助主题用于检索。需要跨主题展示时复用同一 qa_id，通过快照旁路清单保留 ID；用户合并训练集时按 ID 或记录映射去重。

默认按主题导出独立 CSV，总表同样严格六列。XLSX 多工作表为后续导出适配器，处理工作表名称长度/字符限制。后台实体统一管理，不为每个自动新增主题立即创建独立物理数据库表。

主题变更时先更新分表视图或按需重导出，不逐条改写历史 CSV。导出清单保存规范主题版本、QA ID 和文件 hash。业务若最终要求外部数据库独立表，按同一快照及幂等协议追加外部适配器。

### 14.3 路径及导出示意

```text
runtime/exports/<snapshot_id>/
├── QA.csv
├── themes/
│   ├── <topic_id>-<safe_label>.csv
│   └── ...
├── images/                         本快照实际引用的证据图
└── manifest.json                   内部 ID、来源、主题与文件对应关系
```

默认正式 CSV 的 source 第一段和 image 保存处理端持久路径；服务器部署时使用实际服务器文档/图片路径，总表与分主题表保持一致，不随 CSV 所在目录自动改成相对路径。image 为空的记录不复制图片。导出 images 目录作为可选搬迁副本，manifest 保存源路径、asset_id、hash 与搬迁路径。

搬迁到另一台服务器时提供显式重定位：确认新文档/图片路径和内容 hash 后，生成新的迁移快照，更新 source 的文件路径和 image，并保留旧快照及映射。仅下载 CSV 到个人电脑不会自动把服务器路径变成本机可打开路径；网页预览通过后端图片接口，训练消费方按服务器存储约定读取。

先写完整临时快照，验证记录数、六列、关联图、hash 和路径，再原子发布快照或完成标记。一个快照不完整时不覆盖上一份完整快照。备份包含数据库一致性快照、证据、原图、候选及审核；不能只复制打开状态下一个 SQLite 主文件。

## 15. 与同事功能的接口契约

主题匹配和 QA 路径对应通过版本化适配器接入，项目不依赖其内部实现。内部主题 ID 与外部分类 ID 明确映射。

建议交换清单字段：`schema_version`、文件来源及持久路径、完整内容 hash、外部文档 ID、topic_ids/候选主题、匹配状态、理由、真实 page/seg/支持位置、QA 输出目标、图片持久目标和映射版本。三段 source 与图片服务器路径口径同步到接口适配器。

接入时明确：重命名、内容更新、一个文件多主题、未匹配、同名不同义、多个文件共用输出、主题合并以及未知外部 ID 如何处理。映射缺失可以登记待整理，但不能假装路径对应成功。

GLM 不生成任意写入路径。输出位置由存储规则根据稳定 ID 和配置决定；主题名只作为安全显示标签。模板验证路径穿越、保留名称、碰撞和目录权限。本地开发保存本项目 runtime，服务器部署使用管理员配置的允许目录；source/image 可以记录真实绝对路径，但不能成为任意磁盘读取入口。

同事模块未完成时使用本项目内部数据契约和明确的测试适配器开发，测试数据标注为模拟；不声称正式接口已联通。接口完成后替换适配器，不重写生成与审核流程。

所有长任务创建返回作业 ID，客户端查询状态或订阅进度；不要求一个 HTTP 请求持续等到全部文件生成完。认证为本机启动会话，服务只绑定 loopback。以下路径是计划，不是当前可用接口。

## 17. 性能控制与可观测性

### 17.1 设计目标与边界

主流程不等待全库聚类、不逐篇重建全库索引、搜索不让 GLM 阅读全部论文。新增分类输出、索引、审核仍有资源成本；共用已饱和 CPU/磁盘/API 额度时，吞吐可能降低。不能承诺零开销或固定千篇/分钟。

基本名称、别名和已登记分类尽快可查；完整语义索引允许异步延迟。若业务要求立即完成所有语义整理且主流程吞吐不变，则需要额外容量并实测验证。

### 17.2 调度策略

- 总 API 并发受公司限制；主流程保留容量，索引工作低优先级且单独有上限。
- 解析使用有限进程，图像渲染按需，限制同时驻留的大图片和长响应。
- 语义索引批量处理新增项，关系审核只看候选集合，不将全部主题清单反复塞入提示词。
- 高负载时暂停非必要聚类/关系治理，基本登记仍继续；查询扩展也受额度限制。
- 所有队列有积压上限和回压策略，不能无限堆内存。
- 导出批量或按需触发，不能每生成一条 QA 就重写全部主题文件。
- 主题/摘要向量缓存，实体更新按版本失效；模型或维度变化建立新索引版本。

### 17.3 需要记录的指标

准备、分析、生成、审核、修复、提交、导出和端到端耗时分别记录；显示新增合格 QA 数，不能把候选数当最终产量。另记录缓存命中、每模型调用/token/费用、重试、拒绝、未达标、队列积压、索引延迟、搜索 P50/P95 和资源峰值。

用缺失值表达未知费用和不可测指标；使用实际时间测量，不用解析耗时代替完整处理耗时。

### 18.2 必须通过的功能场景

1. 空主题库投入文件，自动形成梗概、关键词及合适的较宽主题，并继续生成 QA；不把每个提取词建成主题。
2. 每篇文章成功归类1–5个正式主题，跨批次不累加超限，整篇主题须考虑后页内容；全库可超过5个主题。QA 按具体考点分别归属，辅助主题不制造重复记录。
3. 同义主题能复用或后台归并，改名/合并后旧引用、搜索及分表仍有效。
4. 正式主题为“数学”、三角函数和圆锥曲线为检索方向时，搜“数学”能展开方向及涵盖文件；搜“圆锥曲线”只返回相应文件，不混入其他数学文件。
5. 已知分类分页能遍历全部结果，不受语义 Top-K 截断；多主题文件不重复计数。
6. 尚未建向量的新主题按基本信息可查，索引失败不阻断 QA。
7. 两字词、别名、中英文及无结果查询有正确行为；语义相关不冒充已知上下位。
8. 文字 PDF、扫描 PDF、独立图像和 CSV 至少各完成一个真实闭环。
9. 不清晰图表、缺少单位、跨单元依赖和知识不足能拒绝或少生成，报告理由。
10. 每篇按累计目标计数，多分片/多主题不各自要求最低 5 条。
11. 重复导入、改名、内容更新、租约失效、晚返回 worker 和重复提交不破坏历史。
12. 断网、鉴权失败、程序关闭、磁盘不足、数据库锁和导出中断可恢复。
13. 未审核或已修改但未重新审核的候选不能提交；source 或图片越界被拒绝。
14. 导出 CSV 引号、逗号、换行和 UTF-8 正确；source 为三段式且 page/seg 可回查，保留字符可以还原；image 为真实持久路径，服务器迁移通过显式路径映射保持可用。
15. 安装包、前端、日志、请求和备份中无明文凭据；远程 AI 路由仅到公司允许服务；本地开源主题嵌入按已授权模型清单运行。
16. 页面只包含文件处理与主题模糊搜索；QA 六字段及原图在文件处理内展开，搜索结果能查看涵盖文件。
17. 论文内嵌图与矢量图均可保存成真实图片，服务器保存未完成时禁止提交相关 image；审核也确实收到图片内容。
18. 已有宽主题能覆盖的新细词不会创建正式主题或新表，同义主题自动复用；跨领域只是相似的主题不会被错误归并。
19. 500 篇试验分别报告原始细词数、正式主题数、新增主题理由、覆盖和具体词召回；减少正式主题不靠丢弃知识点或扩大 QA 结论。

### 18.3 人工质量验收

先建立 30—50 份代表性资料的人工标注集，覆盖中英文、扫描、图表、公式、多主题、模糊/不足和重复资料。主题名称、上下位关系、文档匹配和 QA 质量分别评价；自动生成者评分不能替代标注。

指标包括正式主题数量/增长、归类覆盖、同义复用、宽主题归并准确性、检索词保留、宽泛及具体查询文件召回、QA 事实支持、独立可理解性、范围准确性、考点重复率及人工修改比例。分类更少但覆盖或检索下降不能算达标；关系类型区分同义、方向归属和仅相关。

质量与性能阈值在真实试点前写入验收配置，由团队依据可接受风险和资源确定；未确定或未达标时自动提交发布门槛不通过。当前没有实测阈值或合格率，不声称已达到某百分比。

### 18.4 500 篇性能试验

在独立测试工作区执行四组：纯 QA；QA＋基本主题登记；QA＋受限后台语义索引；QA＋后台索引＋并发搜索。固定模型、规则、资料版本和人工质量评价，重复运行并分别记录冷/热缓存。

比较每分钟最终合格 QA、端到端总耗时、费用、搜索 P95、索引延迟/积压、CPU/内存/磁盘峰值，同时比较关键词数量和正式主题数量，评估归并是否合理。索引速度快但积压持续增长不能算达标；不能通过少审核、截断证据、丢检索方向或降低题目质量换吞吐。

### 21.18 简短主题与独立分类维度（2026-10-19）

用户截图仅用于说明粒度，不据此预置“鱼类”“贝类”“生物细胞”等固定标签，也不让后续其他领域向这些名称靠拢。归类优先参考原文关键词和全文，核心对象能可靠判断时保留一个常见对象类别，再按主要领域或过程补充有独立检索价值的主题；每个主题只表达一个分类概念：对象名称不附加领域/过程/方法，过程名称不附加对象限定；即使组合名不足6字也分别命名，对象与过程不当成冗余上下位合并。同一类别不同物种的资料可以共享对象主题，不同对象涉及相同过程也可共享过程主题。名称通常2–6个中文字，必要的完整专业术语可更长；不会机械截字、删除词义或给所有主题套固定后缀。具体物种、品种、仪器参数、步骤和长修饰语保留为有证据的检索词。

每篇正式主题仍为1–5个，不要求凑满；多维归类各自绑定真实支持单元，不把某一维度的支持自动扩成全文，不堆叠同义或冗余上下位主题。新主题可暂时只有一篇，全库总数不限；有价值的独有主题仍允许，不能替代适用的通用对象分类。已有目录中的长标签不是必须照抄的范本，本轮归类提示取消了长串海洋类别示例，减少示例偏向。

实现只调整原有内容读取/整篇归类提示，短文件仍一次分类，长文件仍在原有首批QA生成中完成整篇命名；不新增拆主题、改名或复审模型轮次，不按示例建立规则词典，不为此重跑全库。每文件检索词最多10个、QA生成数量、完整证据/真实图片及审核要求不变。通常2–6字是生成建议，不增加按字数拒绝、重试或截断的分支；避免为主题简化反复请求模型。额度优化是减少重复输入、冗余输出和无必要调用，不新增按累计消耗阈值停止生成的功能；达到自行估计的费用数值仍继续正常处理。供应商实际请求失败仍沿用现有错误与恢复流程，不用模拟结果冒充成功。
