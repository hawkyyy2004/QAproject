# OceanPile 全流程业务开发规划（讨论稿）

版本：v0.1  
编写日期：2026-11-06  
适用项目：OceanPileQA / QAproject  
文档性质：预计业务开发方案，供需求讨论与后续拆分实施；不是已实现功能说明。

## 1. 规划目标与实施边界

将现有工具逐步建设为一套支持 **资料接入 → OceanCorpus 资料加工与管理 → OceanInstruction 指令加工 → 审核入库 → 兼容导出** 的工作工具。

目标包括两个方面：

1. **成果兼容**：参考浙大公开仓库的实际文件，对齐不同成果的字段、字段含义、图片组织及导出形式。
2. **方法参考**：参考论文中的资料预处理、知识层级组织、指令合成和质量控制方法，形成可追溯、可更新的业务流程。

“成果兼容”与“方法完全复现”需要分别验收。公开说明未给出完整提示词、知识层级、外部知识库、全部阈值及逐条数据血缘，当前不能承诺完全复现浙大内部流程或生成相同内容。

本轮仅形成规划文档，不修改应用代码、配置、正式数据及历史成果。后续按阶段实施，现有 QA 功能必须保留。

### 1.1 范围安排

| 范围 | 安排 |
| --- | --- |
| OceanCorpus | 规划网页知识、论文处理成果、图片及标注三类业务 |
| OceanInstruction | 规划文字、科学图表、声呐、生物识别四类指令加工 |
| OceanBenchmark | 暂不开发，后续另行规划 |
| 生成质量审核 | 持续保留，不能因暂缓 Benchmark 而取消 |
| 训练与模型评测 | 本规划交付训练资料，不包含模型训练平台或评测平台 |
| 模型服务 | 延续统一公司 GLM 适配器，不因参考论文而改用其他远程模型服务 |
| 历史数据 | 保留来源、冻结证据、审核记录及原有导出能力，不静默改写 |

### 2.2 已确认的参考结构

OceanCorpus 当前公开目录分为：

| 分支 | 主要内容 | 成果用途 |
| --- | --- | --- |
| `Web` | 网页实体条目、解释、来源和原文 | 网页知识资料 |
| `Paper` | PDF、解析后的 Markdown、图片和论文索引 | 论文多模态资料 |
| `Open-Dataset` | 生物和声呐图片，以及参考指令 JSON | 图片及标注资料 |

实际文件与说明存在更新不同步的情况。例如，README 仍引用 `Web/data.csv`，当前目录实际保留 `Web/wiki_updated_full.csv`。因此，实施前应固定参考版本，以实际文件核实结构，以论文理解方法；遇到冲突记录差异，不能自行推测为官方规范。

### 2.3 官方内容支持的总体关系

论文将 OceanCorpus 作为基础多模态资料集合；指令合成以文字文档或图片及描述、标签等为输入，结合 OCG 知识层级和相关权威知识，生成并核验指令问答。

据此，本项目拟建立上游资料成果与下游指令成果的关联。该关联不意味着：

- 所有文件都必须先变成七字段网页知识条目。
- 七字段条目是所有指令唯一的生成依据。
- 当前公开 Corpus 已提供全部 Instruction 原件及逐条映射。

## 3. 当前项目与目标之间的差距

以下为编写时的源码状态概括，后续以实际版本为准。

| 环节 | 当前状态 | 预计开发方向 |
| --- | --- | --- |
| 资料接入 | 支持本地文件和可选目录资料库 | 增加网页来源、图片标注及资料包接入 |
| 知识条目 | 从导入文件可读文字提取实体和解释 | 区分网页知识与论文实体事实，明确来源语义 |
| 论文解析 | 有文字证据、真实图片及 MinerU 版面适配 | 补齐独立论文成果包、索引及版本管理 |
| 图片处理 | 支持真实图片参与 QA 生成和审核 | 增加类别、框、图注、来源标注管理 |
| 上下游关联 | 知识整理与 QA 为独立任务，QA 不依赖统一 Corpus 成果版本 | 共用可复用的资料成果，并登记生成血缘 |
| 知识组织 | 有文件/QA 检索主题及八类实体类型 | 增加独立的学科与子类层级，用于指导生成 |
| 生成策略 | 主要是统一双语知识问答 | 分别支持科学文字、科学图表、声呐和生物识别 |
| 证据约束 | 当前 QA 仅依据指定登记单元 | 保留原模式；另行设计多证据及补充知识模式 |
| 审核 | 已有模型核验、双语检查、查重、修订及人工入库等 | 复用并补齐各任务类型标准，完善一致的审核入口 |
| 导出 | QA 统一六字段，知识条目七字段 | 保留原导出，新增按官方子集的兼容导出 |

### 3.1 对现有知识条目的业务定位修正

当前知识条目的解释由公司 GLM 根据导入文件原文整理，不是联网查询得到的百科解释。普通 PDF 的 `page_urls` 为空，`page_titles` 默认取文件名。

当前 `full_text` 是支撑事实的冻结文字单元；同文件实体汇总时可能汇集多个单元。它不是模型生成的正文，但也不能直接称为官方网页全文语义的完全复现。

现有论文实体事实仍有检索和生成辅助价值，应保留来源及历史审核，不删除、不伪装为网页采集成果。

## 4. 预计总体业务流程

```text
资料接入、来源登记与版本识别
                ↓
按业务类型解析、清洗、关联图片与标注
                ↓
冻结并审核 Corpus 成果版本
    ┌───────────┼───────────┐
    网页知识       论文成果       图片与标注
    └───────────┼───────────┘
                ↓
选择证据、关联学科与子类、确定生成任务
                ↓
按需登记并核验补充权威资料
                ↓
生成 OceanInstruction 候选
  Science / MultiModel-Science / Sonar-Open / Bio
                ↓
本地校验、模型审核、修订、人工核对与入库
                ↓
按参考版本导出 CSV、关联图片及适用的资料成果包
```

这是本项目建议的目标流程，不是对官方未公开内部实现的逐步复刻。

### 4.1 任务依赖关系

- Corpus 整理可独立执行，不要求立即生成 QA。
- 新指令任务应引用已就绪的 Corpus 版本，不读取尚未完成或未通过必要校验的中间成果。
- 用户可选择连续处理，由后台依赖任务依次推进，不必先手工下载再重新导入。
- 同一资料被用于多个任务时，复用已验证的解析与清洗成果，避免重复处理。
- 上游失败时下游显示等待或阻塞原因，不能显示为成功生成零条。
- 资料本身有效但不足以形成合格指令时，记录证据不足，不编造内容补数。

### 4.2 文件类型不等于业务类型

PDF 可以是论文、教材或网页打印件；CSV 可以是观测数据、实体表或图片标注表。PNG 也可能是科学图表、声呐图或生物照片。

接入时需要识别“内容与用途”，允许用户在文件详情纠正业务类型。不能仅按扩展名决定全部处理路径，也不能将观测数据强行变为实体词典。

## 5. 资料接入与来源登记

### 5.1 预计接入方式

| 接入方式 | 处理目标 |
| --- | --- |
| 本地上传、目录资料库 | 继续支持已有文件能力 |
| 网页 URL、已采集网页文件 | 保存可追溯网页内容与来源 |
| 图片及标注文件 | 关联图片、类别、框和描述 |
| 已有 Corpus 成果包 | 校验并登记已有加工成果，避免不必要的重新生成 |

目录、压缩包及大文件导入属于预计能力，不能将现有上传限额和内存读取方式描述成已经支持全量公开数据。

### 5.2 建议登记的信息

内部记录资料 ID、来源类型、原始位置、内容 hash、获取时间、版本、标题、来源数据集及已有授权说明等。字段按用途保存，不要求所有资料都具备作者、DOI 或网址；未知值不由模型补造。

来源登记不等于科学内容已审核。解析成功、清洗完成、事实审核通过和可用于生成需要分别记录。

### 5.3 服务器原件存放与追溯（用户已确认）

项目后续部署到服务器，用户将原始资料上传到服务器资料库。应用以该处原件为准，OceanCorpus 在业务上登记、关联这些资料，不要求再复制一套原件到独立的 Corpus 目录。

系统内部保存稳定资料 ID、服务器原件位置、内容 hash/版本及真实证据位置。用户从知识条目、论文成果或 QA 详情可以回查原始文件，查看其服务器存放位置，并通过受控入口打开或下载。原件目录内可以包含 PDF、图片及其他支持的资料类型。

原件路径用于定位，hash/版本用于确认仍是生成时的同一份文件。原件移动、删除或被替换时明确提示，不能把旧成果静默关联到同名新文件。已保存的解析成果、必要冻结证据、图片及审核历史仍由应用持久保存，不要求每次追溯都重新解析原件。

以上为服务器部署时的目标约定，不表示已经完成上传服务或服务器部署。运行时原件管理与对外导出分别设计：日常不重复复制原件；需要完整可搬运成果包时，再按选定导出规范收集所需文件。内部追溯信息不强行加入官方 CSV 正式列，也不向前端开放任意服务器路径读取。

## 6. OceanCorpus 三类成果开发

### 6.1 网页知识

预计流程：

1. 登记 URL 或导入网页内容，保存原始快照和真实页面标题。
2. 提取正文及相关图片，清除导航、广告等非正文内容。
3. 保存清洗结果及与原始快照的映射，不覆盖原始内容。
4. 根据正文提取实体、类型和解释，并核验事实及适用范围。
5. 多来源事实分别保留证据关系，通过审核后形成可查询与导出的知识成果。

对齐参考文件：`Web/wiki_updated_full.csv`。

| 字段 | 预计处理约定 |
| --- | --- |
| `entity_name` | 原文支持的实体名称，保留必要消歧信息 |
| `entity_type` | 对齐八类实体类型；不能容纳的内容不强套分类 |
| `entity_description` | 根据已登记来源整理并通过审核的解释 |
| `page_urls` | 实际采集来源网址，不把正文中的任意链接当整体来源 |
| `page_titles` | 对应网页真实标题 |
| `full_text` | 与来源对应的正文内容；多来源组织方式需核实后固定规范 |
| `full_text_length` | 最终导出文本的实际字符数，并核对官方计数口径 |

八类实体为 Location、Instrument、Organism、Process、Phenomenon、Substance、Property、Theory。

**边界**：不能在没有抓取网页时补写网址；不能用模型记忆代替网页原文；不能将网页更新后的内容静默替换历史证据。

### 6.2 论文与教材处理成果

预计流程：

1. 登记原件并执行结构化解析。
2. 保存正文结构、标题层级、表格、公式、图片及图注关系。
3. 清理页眉、页脚、水印、重复模板等外围内容，保留清洗记录。
4. 形成 Markdown、关联图片及论文索引，并校验文件引用。
5. 将可用文字与视觉证据登记为下游生成输入。

对齐参考索引：`Paper/CleanedData/papers.csv`。

| 字段 | 参考文件含义与预计要求 |
| --- | --- |
| `paper_id` | 稳定论文标识，按选定兼容规范生成 |
| `title` | 官方说明取 Markdown 首个一级标题；需区分内部校正标题与兼容导出值 |
| `pdf_path` | 导出时按选定规范指向原始 PDF；内部另存服务器资料库位置，完整成果包采用包内相对路径 |
| `md_path` | Markdown 相对路径 |
| `images_dir` | 关联图片目录；无图时按参考规范留空 |
| `image_count` | 与该论文关联的实际图片数，口径须固定并可复核 |

索引必须能定位对应文件。服务器日常使用可引用资料库原件，不重复复制；选择导出完整成果包时才收集相应文件并验证包内引用。无图论文可以正常形成成果，不为增加数量生成无意义图片。

现有“PDF 不另导出 Markdown”和图片处理约定与此目标有差异。建议增加独立的 Corpus 成果生产模式，保留原 QA 处理能力，实施时明确更新适用范围，不借规划修改历史冻结证据。

### 6.3 图片与标注成果

拟支持三类资料：科学图表、生物照片和声呐图。图片与类别、图注、框坐标等标注独立管理，并关联到真实来源。

| 内容 | 预计业务处理 |
| --- | --- |
| 原始图片 | 保存完整原件与来源，按资产 ID 访问 |
| 科学图表 | 保存图注、相关正文及表格等上下文 |
| 生物类别 | 保存原始标签与规范标签，未知类别不强行命名 |
| 检测框 | 保存原始坐标及坐标格式，转换时记录图片尺寸和转换规则 |
| 模型建议标注 | 与可信原始标注区分，审核前不当作标准答案 |
| 描述 | 仅根据图像、可信标签与登记上下文补充，并独立核验 |

官方部分声呐参考 JSON 含 `image_path, object, bnd_box, input, output`；生物参考 JSON 含 `image_path, category, prompt`，另有 `messages/images` 形式。它们是不同用途的参考结构，不宜合并成一种固定标签表。

坐标是归一化值还是像素值、类别能否合并、路径如何映射，都必须显式确认，不能靠字段名猜测。官方也说明部分 JSON 与图片目录不能直接对应，导入后必须校验。

## 7. 知识组织与补充资料

### 7.1 三类分类分别管理

| 分类 | 用途 | 与现有系统关系 |
| --- | --- | --- |
| 正式主题与检索词 | 文件和 QA 搜索 | 保留现有规则及历史映射 |
| 实体类型 | 区分知识条目种类 | 保留八类类型 |
| 学科与子类层级 | 指导出题和检查知识覆盖 | 预计新增独立结构及版本 |

论文中的 OCG 重点是学科与子类组织。不能把当前主题表换个名字就宣称完成 OCG，也不必为此立即引入专门图数据库。

建议先获得浙大可提供的层级或专家确认的基础分类，再增加资料与子类的证据关联、同义名称整理和版本更新。论文所述子类过滤方法需结合本项目约束讨论，不能直接用于删除现有允许保留的独有检索主题。

### 7.2 补充权威知识模式

保留当前仅依据指定证据生成的默认模式。后续另设补充知识模式：

1. 根据任务检索已登记的权威资料，必要时采集新资料。
2. 保存真实内容、来源、版本和原文位置。
3. 核验资料相关性与事实可用性。
4. 将主资料和补充资料共同登记为本题的证据集合，再生成问答。
5. 审核区分直接观察、原文结论及补充解释，避免扩大研究结论。

该模式会改变当前单单元证据约定，属于后续专项开发。未实现前，不允许模型用未登记常识补答，也不能把已有主题摘要当作事实证据。

## 8. OceanInstruction 指令加工

### 8.1 按任务类型生成

| 子集 | 预计输入 | 预计生成行为 |
| --- | --- | --- |
| Science | 论文、教材、网页的已审核可用文字证据 | 概念、机制与科学事实问答 |
| MultiModel-Science | 科学图表、地图、示意图及相关上下文 | 图像理解、比较、关系与科学解释 |
| Sonar-Open | 声呐图及可信类别、框或描述 | 目标识别、描述和适用的定位任务 |
| Bio | 生物照片及可信类别标签 | 按任务规定输出物种或类别名称 |

一份资料可支持多个任务类型，但每条指令必须记录自己实际使用的资料版本和证据，不能继承整份资料的所有事实。

### 8.2 现有生成策略的保留与扩展

- 保留原有双语生成、审核、修订、确认入库、编辑重审、检索及六字段导出。
- 每篇约 5–7 组、视觉最多 2 组、简短答案等继续作为原有策略，不作为官方所有子集的强制规则。
- 新策略按证据和任务覆盖分配数量，不凑题；不因长论文达到旧默认数量就声称完成全量知识覆盖。
- 生物识别可要求严格标签输出，不强制套用普通论文问答的解释形式。
- 双语记录是否成对输出、语言取值及答案样式按兼容规范确定；官方公开资料不足以证明所有样本一一双语配对。
- 当前 `thinking` 是简短依据摘要，不能未经核实等同于官方描述的 CoT 内容；内部依据和对外字段需分别定义。

## 9. 审核、入库与更新

### 9.1 两个阶段分别审核

**Corpus 审核**检查解析是否完整、清洗是否损失有效内容、图文引用是否正确、来源是否真实、类别与坐标是否有效、条目解释是否有依据。

**Instruction 审核**检查事实支持、问题是否自含、适用范围、任务类型、图像理解、标签与框的一致性、语言等义、重复考点及输出格式。

解析通过不等于科学内容正确，模型审核通过也不冒充专家已核查。人工仅点击确认入库与实际逐项复核应在审计中明确区分。

### 9.2 预计状态与恢复

拟区分来源已登记、解析中、待清洗核验、Corpus 可用、生成中、待审核、待修订、待人工核对、已入库及失败等状态。具体状态机在实施阶段细化，避免一个“完成”混淆上下游进度。

继续复用任务租约、同文件互斥、受控并发和成功批次恢复。知识整理、QA 生成与搜索不能通过多开应用进程叠加并发。

上游变化产生新版本，下游标记关联版本及是否需更新。历史指令继续绑定原证据，不能让新解析结果静默替换旧审核依据。

### 9.3 质量评分的安排

现有必要审核持续运行。更完整的评分维度、专家抽检、争议处理及阈值可后续完善；它们与 OceanBenchmark 建设是不同事项。

论文采用的多模型或多验证主体方法，与本项目公司模型限制存在实施差异。可先明确可用审核方式及验证主体，不能将同一模型多次调用描述成不同模型共识。

## 10. 内部数据与官方兼容导出

### 10.1 内部记录建议

拟建立来源资料、Corpus 成果版本、证据单元、图片资产、标注、实体事实、知识层级、生成任务、指令版本、审核记录和导出快照之间的关联。

这些是建议的业务对象，不是已经创建的数据库表。稳定 ID、hash、主题、审核状态、配对 ID 等保存在内部，不因内部需要而扩展官方正式列。

### 10.3 预计导出原则

1. 保留当前六字段导出，新增按子集和参考版本选择的兼容导出。
2. 自定义检索主题和标签不增加为官方导出列；官方原生的实体类型、类别标签不因“去掉自定义标签”被误删。
3. `image` 与 `image_path`、语言编码及列顺序通过导出映射转换，不能简单沿用内部字段。
4. 当前三段式 `source` 含自定义主题，与官方样例来源标识语义不同；兼容模式应单独定义，未知映射明确提示，不能编造官方来源值。
5. 图片按固定包根目录使用可解析的相对路径，导出时验证文件存在、内容正确、引用完整。
6. 论文成果包检查 PDF、Markdown 和图片目录引用；只有索引表不算完整交付。
7. 导出绑定固定快照，处理并发新增内容不能导致本次结果前后不一致。
8. 不附带密钥、运行数据库或内部审计文件；交付所需语料与图片仅进入用户指定的数据成果包，不进入源码仓库。

## 11. 页面与操作预计调整

优先复用现有四模块，避免先增加大量独立页面。以下为建议，具体交互另行确认：

| 模块 | 预计职责 |
| --- | --- |
| 文件处理 | 统一接入资料，查看 Corpus 与指令任务及依赖，处理错误和重试 |
| 主题模糊搜索 | 保留现有搜索，后续增加有证据关联的资料成果检索 |
| QA 汇总 | 保留全部原功能，增加指令子集、来源成果和兼容导出 |
| 知识条目汇总 | 逐步扩展为 Corpus 成果汇总，区分网页知识、论文成果、图片与标注 |

生成入口可支持“仅整理资料”“从已就绪资料生成指令”“整理并连续生成”。具体文案与现有三选项如何兼容，留到交互实施阶段确定，不在本规划中视为已替换。

用户不需要手工下载上游产物再上传给下游。同一资料可在详情继续生成其他类型的成果，已有成功结果及版本保持可查。

## 12. 分阶段开发与验收

### 阶段一：固定兼容规范与业务边界

交付：参考版本清单、各类成果字段定义、路径规则、样例包和差异清单。

验收：逐个子集核对表头、值域及文件引用；区分官方要求、本项目保留规则和待确认项，不将列名一致作为全部验收。

### 阶段二：统一 Corpus 成果基础

交付：来源登记、成果版本、证据关联、可复用解析结果及任务依赖。

验收：一份资料可只整理不生成 QA；后续指令能引用指定成果版本；上游失败下游不误启动；已有 QA 功能和历史证据保持正常。

### 阶段三：优先打通论文完整链路

交付：PDF → 正文/Markdown/图片/索引 → 科学文字与图表指令 → 审核 → 对应子集导出。

验收：用可读文字论文、图文论文、扫描资料及无图资料分别验证；文件引用完整，图文可回查，失败与证据不足明确区分。

这是建议首先完成的端到端链路，原因是现有解析、图片、QA 和审核能力可复用最多。耗时以实测为准，不预设完成日期或零性能影响。

### 阶段四：网页知识链路

交付：URL/网页内容 → 快照与清洗 → 实体条目 → 文字指令。

验收：网址、标题、正文与解释相互可查；网页更新产生新版本；无来源不编造解释；导出字段与选定规范一致。

若团队近期任务仍集中于知识条目，可在阶段二后优先安排本阶段；不要把论文实体提取继续冒充网页采集。

### 阶段五：图片与标注链路

交付：图片及原始标注 → 标准化与核验 → 生物/声呐指令 → 图片包导出。

验收：无标注资料明确待处理；错误类别和框被拦截；图像路径可解析；生物标签输出和声呐描述符合各自任务规范。

### 阶段六：知识层级与补充知识

交付：可版本化的学科与子类结构、生成覆盖检查、有来源的补充知识模式及对应审核。

验收：检索主题、实体类型与出题层级相互独立；补充事实可回查；不能把未登记模型常识当来源。该阶段完成前只声明基础流程兼容，不声明已经复现 OCG 增强合成方法。

## 13. 小规模全链路验收要求

先建立隔离验收样本，不将测试内容默认注入正式界面。

| 样本 | 重点验证 |
| --- | --- |
| 网页及其更新版本 | 抓取、标题、正文、来源、版本与实体事实关系 |
| 普通文字论文 | 正文完整、清洗映射、Markdown 和文字 QA |
| 含图表论文 | 图像、图注、正文关联和图表 QA |
| 扫描资料 | 无文字层识别、真实图像保留与能力限制提示 |
| 无图论文 | 无图仍可形成完整论文成果 |
| 生物图像及标签 | 标签可信性、类别输出与图片路径 |
| 声呐图及框 | 类别、坐标转换、定位与描述一致性 |
| 文件变化、缺失和失败恢复 | 历史证据不变、下游阻塞、续跑和导出拦截 |

每条正式指令应能回查到原始资料、Corpus 版本、实际使用证据和审核版本。导出后在不同目录验证相对路径可用。

区分自动测试、真实公司接口验证与专家质量验收。性能分别记录解析、清洗、生成、审核、提交、导出及端到端耗时，区分从头处理和复用续跑。

## 14. 与浙大确认后才能固定的事项

| 待确认事项 | 对开发的影响 |
| --- | --- |
| 当前合作验收采用哪个仓库 revision | 决定兼容规范和导出目标 |
| Web 多来源正文、解释与分隔符组织规则 | 决定 `full_text` 和来源关系如何组装 |
| 各子集 `source` 的含义、允许值与新增来源命名 | 不能将本地路径或官方样例值直接套用 |
| Science 的 `thinking` 实际要求 | 区分依据摘要、空值和目标推理内容 |
| 图片路径根目录、归档形式及标签映射 | 决定成果包和训练端是否能读取 |
| OCG 层级、提示词、补充知识及处理代码能否提供 | 决定能否从方法参考推进到更精确复现 |
| 审核维度、阈值、专家流程及可用模型 | 决定质量方法的可复现程度 |
| 论文描述规模与公开文件范围的关系 | 避免把公开快照当完整内部资料库 |

这些信息未齐全时，仍可推进统一来源、成果版本、证据关联和论文成果等不依赖未知值的工作；尚未核实的导出语义不得标为“完全一致”。

## 15. 第一版预计交付边界

建议第一版以“统一 Corpus 基础＋一条论文端到端链路＋现有功能无减少”为可评审目标，同时明确网页、标注、OCG 和补充知识的阶段状态。

完成第一版后，用户应能投入一篇论文，查看其资料处理成果，基于明确的资料版本生成和审核文字/图表指令，最后导出指定子集格式及关联文件。

原有知识条目、QA、审核与导出保留。后续逐步补齐网页和图片链路，最终让同一个工具承担整条资料加工与指令生产工作，而非要求所有资料都先转成同一种知识条目。
