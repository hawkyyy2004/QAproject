# OceanPile资料加工业务规范与开发边界

更新日期：2026-11-11。此文档是当前方案，已替换旧讨论稿；实现状态以README及源码为准。

## 1. 当前范围

本轮优化OceanCorpus资料整理与知识条目：统一成果语义、网页清洗与配图、论文结构、图片及参考标注。QA入口调整为自动先归档资料再生成，复用一次冻结证据；已有QA/Instruction生成和审核策略保持原有行为，不借本轮修改数量、提示词、模型、候选、查重或入库规则。

产品保留文件处理、主题模糊搜索、QA汇总、资料汇总四模块。资料汇总包含资料成果、知识条目、知识层级。处理记录分别为QA生成、知识条目整理、资料整理。上传处理方式为三个独立勾选项，不增加重复入口。

## 3. 业务流程

```text
接入文件、服务器目录原件或指定网页
                    ↓
来源登记、原件内容校验、统一后台排队
                    ↓
        按资料类型独立加工
      ↙             ↓             ↘
网页正文与配图    论文结构/全文    图片与来源标注
      ↘             ↓             ↙
清洗、近重复核验、保存原图与加工记录
                    ↓
不可变Corpus版本（资料归档完成）
                    ↓
独立分支：QA生成、可选知识条目、参考标注与资料包
```

“资料归档完成”不等同全文科学审核完成。知识条目、图片可用性和已有QA审核各有自己的证据与状态，不能共用一个“通过”标签暗示全部完成。

## 4. 字段与来源口径

### 网页及实体七字段

`entity_name,entity_type,entity_description,page_urls,page_titles,full_text,full_text_length`

- 解释由当前来源正文支持，不让模型用常识补定义，不自动互联网搜索。
- 网页解释与论文事实按真实来源区分；论文可以产出实体事实，但不伪装为Web采集成果。
- `full_text`是匹配事实证据hash的冻结来源全部可读正文，按原顺序连接、完全重复段落只保留一次；不是模型复写，也不是单条quote。
- 有匹配Corpus优先使用该不可变版本；没有时使用知识任务自己的冻结全文；知识CSV按实际来源记录隔离，不能把不同网页拼成一个全文。绑定缺失拒绝导出，不混用最新不匹配版本。
- 知识条目与网页Corpus共用正文组装函数；长度按实际导出字符串计算。详情显示独立导出视图，旧审核行和hash保留。
- 八类实体类型独立于检索主题和知识层级；同文件同名同类型可汇集事实，不跨来源自动消歧。

### 论文六字段

`paper_id,title,pdf_path,md_path,images_dir,image_count`

只有真实PDF论文输出此索引；路径与实际包内文件匹配，无图片时计数0、图片目录为空。保存服务器位置而非重复复制原件；下载资料包时收集所需原件。默认沿用原有解析配置；本机auto优先已有MinerU，复用历史结果或执行本地解析。原生兜底/显式原生以字体、坐标和表格产生阅读稿，复杂公式和扫描件限制明确。显式MinerU失败不静默降级。

### 图片与标注

内部保存类别、框、图注、坐标系、实际尺寸、来源、人工确认状态及hash。外部参考格式：

- 生物：`image_path,category,prompt`。
- 声呐：`image_path,object,bnd_box,input,output`。

参考导入只映射已登记图像，不读取任意路径；归一化框不能越界。类别合并只依据用户提供的显式映射，保留原类别。参考问题文本保留来源原值；无文本留空，不在本轮生成QA。未人工确认的记录仅留内部标注，不能冒充标准答案。

## 5. 清洗与质量

- 网页优先正文容器，排除结构噪声、明确占位文字与长段落完全重复；保留简短定义、条件、单位和表格分隔。
- 正文配图安全采集后传真实图片给统一公司GLM判断相关性和可用性；失败、排除、限额未采集均记录。
- 同一Corpus的近重复候选用文本相似度筛选并由GLM确认；数值、否定不同不合并。只处理限定长度候选，不对全库做语义删除。
- PDF通过实际页边坐标和重复情况清理页眉/页脚，保留原文、保留区间、结构和原图。扫描图不假装已识别为正文。
- 知识提取和独立审核继续绑定逐字片段、事实行及证据hash，失败只留审计。

## 6. 版本与调度

新整理只创建新Corpus版本；旧版本、QA冻结单元、原图、候选和审核不改写。所有任务共用2文件/2模型请求上限及单线程原生解析；图片采集和模型失败可重试，已成功结果有绑定缓存。

正常选择生成QA会自动包含资料整理；已完成资料准备才放行QA和所选知识任务，失败时等待资料重试。原生PDF分支在首轮读取证据时同步提取结构；MinerU分支只由MinerU产出正文，原生处理仅保留原图，不另提取一套正文，质量/归档失败保留已解析检查点。历史已冻结QA不替换证据，显式重新整理默认不触发QA生成。历史的`corpus_qa`接口保留兼容，不作为当前资料优化入口。资料已就绪不表示已经生成下游Instruction；是否发起下游仍遵循已有显式入口。

## 7. 导出与验收

| 项目 | 验收要求 |
| --- | --- |
| Web | 两个出口七字段及全文一致，URL真实，字符长度正确，UTF-8无BOM/CRLF |
| Paper | 六字段、PDF/MD/图片路径一致，UTF-8带BOM/CRLF，页码和表格可回查 |
| 图片资料 | 每条标注路径指向真实包内图，框可验证；已确认/未确认区分；不重复打包同图 |
| 历史保护 | 正式QA/候选/审核及历史证据内容不变，不通过CSV直接修复数据 |
| 异常 | 原件失效、图片失败、模型失败、解析失败和未采集范围可见，不伪造成功 |
| 文档 | README和本文以新方案直接替换过期内容，不追加互相冲突的旧方案 |

本轮不宣称全库语义去重、自动网页检索、完整官方OCG、专家评分或生产服务器部署。真实接口和平台结果分别验收，模拟模型、原生结构测试不能冒充真实MinerU质量对照。本轮已额外用现有MinerU环境实际解析一份隔离PDF，仍不代表全部论文的质量验收。后续待办应围绕这些当前边界制定，不能把计划写成已实现。

## 8. 官方依据和本项目选择

官方论文的数据预处理与Instruction Data Synthesis支持上游资料加工后用于下游合成，但没有公开解析器调用次数、内部任务调度、缓存实现。QA自动保存Corpus与一次准备复用属于本项目工程选择，保持公开的业务关系，不宣称它是官方明确描述的UI或内部算法。知识条目是独立资料分支，不是每份论文生成QA的必经中间表。
