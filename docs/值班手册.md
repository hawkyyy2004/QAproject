## 3. 常见故障处理

### 现象：网页打不开
1. 本机 `ping 192.168.0.145` → 不通 = 网络/WiFi 问题，找 IT
2. 服务器上 `systemctl status qaproject` → 挂了执行 `sudo systemctl restart qaproject`
3. `curl -I http://127.0.0.1:8765` → 服务器本地通但外部不通 = 防火墙/端口问题，找管理员

### 现象：服务反复重启
```bash
tail -n 200 ~/qaproject/runtime/server.log   # 看崩溃前的报错
systemctl show qaproject -p NRestarts
```
带着日志找项目作者（xiang.ying）定位。

### 现象：磁盘快满（df 已用 > 90%）
```bash
du -sh ~/qaproject/runtime/* ~/backups   # 找出占空间的大头
find ~/backups -mtime +14 -delete        # 清理旧备份
```

## 4. 代码更新流程

```bash
cd ~/qaproject
git pull                                # 先看有没有同事的新提交
source .venv/bin/activate && pip install -r requirements.txt   # 依赖有变时
python -m pytest tests/                 # 跑测试
sudo systemctl restart qaproject        # 重启生效
curl -I http://127.0.0.1:8765           # 验证 200 OK
```

### 回滚（更新后出问题）
```bash
cd ~/qaproject
git log --oneline -10          # 找上一个正常版本
git checkout <commit号> -- .   # 或 git reset --hard <commit号>
sudo systemctl restart qaproject
```

## 5. 备份与恢复

- 自动备份：每天 02:00 执行 `deploy/backup_runtime.sh`，保留 14 天，见 `~/backups`
- 手动备份：`~/qaproject/deploy/backup_runtime.sh`
- 恢复方法：
```bash
tar -xzf ~/backups/qa-runtime-日期.tar.gz -C /tmp/restore
# 确认内容后替换 runtime/live（先停服务）：
sudo systemctl stop qaproject
rm -rf ~/qaproject/runtime/live
cp -r /tmp/restore/live ~/qaproject/runtime/
sudo systemctl start qaproject
```

## 6. 日志轮转

配置：`/etc/logrotate.d/qaproject`（源文件在项目 `deploy/logrotate-qaproject.conf`）
每日切割 server.log，保留 14 天，自动压缩。
